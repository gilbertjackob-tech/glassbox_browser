# GlassBox v2.1 Implementation Guide

**Stateful Resume + Site Learning Layer**

This document describes the architecture for transforming GlassBox from linear automation to stateful, resumable task execution.

---

## Overview

Current state (v2.0):
- ✅ Visible Electron BrowserView with profile isolation
- ✅ Local Express API for tabs, DOM, queries, actions, verification
- ✅ SQLite memory for profiles, targets, skills, action logs
- ✅ Micro-skill save/replay
- ✅ Site packs with verified action chains
- ✅ Site room detection and suggestions
- ✅ WhatsApp Web automation (full file upload)
- ✅ Windows right-click context menu integration

**Missing layer (v2.1):**
- ❌ World state capture
- ❌ Tab readiness detection
- ❌ Conditional resume planning
- ❌ Learned site routes
- ❌ Skill promotion from repeated sequences

## New Modules Created

### 1. `src/server/state/worldStateService.ts`

**Purpose:** Snapshot current app/profile/tab/target state.

**Key exports:**
- `WorldState` (interface)
- `getWorldState(tabManager, vlmPageApi, profileId?)` → Promise<WorldState>
- `describeWorldState(state)` → string

**Integration points:**
- Call from new `GET /api/world-state` endpoint
- Called by resume planner before task execution
- Cached with short TTL (1-2 seconds) to avoid repeated DOM queries

**Next step:** Add this endpoint to `apiServer.ts`

```ts
app.get('/api/world-state', async (req, res) => {
  const state = await getWorldState(tabManager, vlmPageApi);
  res.json(state);
});
```

---

### 2. `src/server/state/tabStateResolver.ts`

**Purpose:** Determine if a tab is ready, authenticated, and free of errors.

**Key exports:**
- `TabReadinessInfo` (interface)
- `getTabReadiness(tab)` → Promise<TabReadinessInfo>
- `canResumeTaskOnTab(readiness)` → boolean
- `describeTabReadiness(readiness)` → string

**Integration points:**
- Call from `worldStateService.ts` to enrich each tab snapshot
- Use in resume planning to filter candidate tabs
- Add new endpoint: `GET /api/tabs/:id/readiness`

**Next step:** Add endpoint to `apiServer.ts`

```ts
app.get('/api/tabs/:id/readiness', async (req, res) => {
  const tab = getTabOrThrow(req.params.id);
  const readiness = await getTabReadiness(tab);
  res.json(readiness);
});
```

---

### 3. `src/server/planner/resumePlanner.ts`

**Purpose:** Plan task execution by checking current state and skipping already-done steps.

**Key exports:**
- `ResumeStep` (interface)
- `TaskResumePlan` (interface)
- `planTaskResume(goal, worldState, taskTemplate?)` → Promise<TaskResumePlan>
- `commonTasks` (template library)
- `describePlan(plan)` → string

**How it works:**
1. Input: Natural goal ("Send file to Bihi") + current WorldState
2. Lookup task template (or infer from goal)
3. Evaluate each step's `alreadyDoneCheck` against current state
4. Mark steps as "skip" or "execute"
5. Return plan with confidence score

**Integration points:**
- New endpoint: `POST /api/tasks/prepare`
- Input: `{ goal: string, profileId?: string, taskTemplate?: ResumeStep[] }`
- Output: `TaskResumePlan`

**Next step:** Add endpoint to `apiServer.ts`

```ts
app.post('/api/tasks/prepare', async (req, res) => {
  const { goal, profileId, taskTemplate } = req.body;
  const worldState = await getWorldState(tabManager, vlmPageApi, profileId);
  const plan = await planTaskResume(goal, worldState, taskTemplate);
  res.json(plan);
});
```

---

### 4. `src/server/learning/siteLearningService.ts`

**Purpose:** Store verified actions as learning events for reuse and skill promotion.

**Key exports:**
- `SiteLearningEvent` (interface)
- `initializeSiteLearningSchema(db)` → void
- `recordSiteLearningEvent(db, event)` → void
- `queryLearnedActions(db, profileId, host, actionType?, room?)` → SiteLearningEvent[]
- `recordRoute(db, profileId, host, roomFrom, roomTo, sequence, success)` → void
- `shouldPromoteToSkill(db, sequenceHash)` → boolean
- `describeLearningState(db, profileId)` → string

**Database tables added:**
- `site_learning_events` — verified user/agent actions
- `site_routes` — common navigation patterns
- `skill_candidates` — repeated sequences candidate for promotion

**Integration points:**
- Call `initializeSiteLearningSchema(db)` in `memoryDb.ts` during setup
- After every verified action in `vlmPageApi.ts`, call `recordSiteLearningEvent()`
- Query learned selectors in target resolution fallback

**Next step:** Integrate with existing action logging

```ts
// In vlmPageApi.ts, after verified action:
if (verification.ok) {
  recordSiteLearningEvent(db, {
    id: `evt_${Date.now()}`,
    profileId: tab.profileId,
    host,
    room: detectedRoom,
    actionType: 'click',
    targetLabel: target.label,
    selector: target.selector,
    beforeHash: hashDom(before),
    afterHash: hashDom(after),
    success: true,
    confidence: 0.95,
    createdAt: new Date().toISOString(),
  });
}
```

## New API Endpoints (v2.1 addition)

```
GET  /api/world-state
     Returns current app/profile/tabs/targets snapshot
     
POST /api/tasks/prepare
     Input: { goal, profileId?, taskTemplate? }
     Returns: TaskResumePlan with skipped/next steps
     
POST /api/tasks/resume-run
     Input: TaskResumePlan + runOptions
     Returns: ExecutionResult with evidence
     
GET  /api/tabs/:id/readiness
     Returns TabReadinessInfo (auth, loading, errors)
     
GET  /api/tabs/:id/room-state
     Returns detected room, signals, confidence
     
GET  /api/learning/site/:host
     Returns learned actions for this host
     
POST /api/learning/promote-skill
     Input: { sequenceHash, skillName, isDestructive }
     Returns: promoted skill or error
```

## Example: WhatsApp File Send Resume

**Task:** "Send file to Bihi"

**Current state:**
- ✅ GlassBox running
- ✅ Profile "test" active
- ✅ WhatsApp tab exists and loaded
- ✅ Chat with Bihi already open
- ❌ File not attached

**Resume plan output:**
```json
{
  "status": "READY_TO_RESUME",
  "skippedSteps": [
    { "stepId": "ensure_app_running", "reason": "Already done" },
    { "stepId": "ensure_profile_active", "reason": "Already done" },
    { "stepId": "ensure_whatsapp_tab", "reason": "Already done" },
    { "stepId": "ensure_target_chat_open", "reason": "Already done" }
  ],
  "nextSteps": [
    { "id": "attach_file", "action": "whatsapp_attach_file", ... },
    { "id": "send_file", "action": "whatsapp_send_file", ... }
  ],
  "skippedStepsCount": 4,
  "confidence": 0.95
}
```

**Result:**
- Saves 4 steps (app launch, profile open, tab open, chat search)
- Direct execution of file attach + send
- 30-50% faster than cold start

## Testing Strategy

### Unit Tests
- `worldStateService.ts`: Mock tabs, verify snapshot shape
- `tabStateResolver.ts`: Mock tab.webContents, test readiness logic
- `resumePlanner.ts`: Test condition evaluation and step skipping
- `siteLearningService.ts`: Test DB schema and queries

### Integration Tests
- Test WhatsApp file send with pre-open chat
- Test ChatGPT prompt send with pre-focused composer
- Test GitHub issue open with pre-loaded repo
- Test browser not running → normal cold start

### Acceptance Tests
```
Given: ChatGPT is already open and composer is focused
When: /api/tasks/prepare called with goal="Send 'hello' to ChatGPT"
Then: Returned plan should skip all setup steps
And: nextSteps should only contain 'type_prompt' and 'send_prompt'
And: confidence should be > 0.9
```
